# 직접 번역·전수 문맥 검수

2026-08-31 사용자 승인: 외부 API 없이 Codex가 직접 번역하고 검수할 수 있다. API 크레딧 부족은 번역 자체의 불가 사유가 아니다. 이 절차는 기존 API 전용 게이트를 대체하지만 품질·누락·배포 게이트는 완화하지 않는다.

## 두 가지 실행 경로

- 직접 경로: 현재 작업의 Codex가 원문과 화자를 읽고 번역한다. 초벌 저장 후 모든 대사를 원문·앞뒤 문맥과 다시 대조하는 별도 검수 패스를 수행한다.
- API 경로: 사용자가 지정한 번역/검수 모델과 기존 자동화 스크립트를 이용한다. API 사용이나 모델 변경을 강제하지 않으며, 직접 작업을 API 검수 결과로 표현하지 않는다.
- 같은 작업자가 번역과 재검수를 했다면 독립 검수자나 별도 모델의 검수라고 주장하지 않는다. 자동 검사 통과를 의미·문맥 검수로 대신할 수 없다.

## 작업 및 기록

1. 최신 캐시의 신규/변경 시나리오 ID, 네 가지 메시지 명령, 정확한 source key, 화자 및 순서를 고정한다. 원문 인덱스 해시와 범위를 기록한다.
2. 원문 전체와 캐릭터 카드/용어집을 읽고 번역한다. 사건의 주체·시간·인과관계·감정·말투·호칭·중의성을 보존한다. 문장이 길다는 이유로 정보를 임의로 버리지 않는다.
3. 초벌 저장 후 각 시나리오를 처음부터 끝까지 다시 읽는다. 원문과 한국어를 함께 보며 모든 엔트리와 중복 key의 서로 다른 등장 문맥도 확인한다. 짧은 `men_`와 `hmr_`도 제외하지 않는다.
4. 검수 기록에 시나리오 ID, 메시지/고유 key 수, 실제 검수 범위, 발견 문제와 수정/기각 근거, 최종 번역 파일 SHA256을 남긴다. 검수 후 의미를 수정하면 관련 문맥을 다시 검수하고 해시를 갱신한다. 읽지 않은 항목에 일괄 완료 도장을 찍지 않는다.
5. UI는 원문 필드·수치·조건·대상·색상·자리표시자와 조합 변형을 확인한다. 수치만 다른 문구는 검수된 동일 구조를 기계적으로 확장할 수 있지만 수치 보존을 검사한다.
6. 신규 파일별 및 커밋 전 변경 파일 전체의 34자 목표/36자 상한/최대 두 줄 레이아웃 검사를 실행한다. JSON·태그·일본어 잔존·화자명·용어·원문 key 누락 검사를 실행한다.
7. 전수 검수와 모든 blocking 검사 통과 후 매니페스트를 생성한다. 그다음 repo/manifest/게임 캐시의 ID·key·해시 일치를 검증하고 배포한다. 검수 전의 source/repo 검사와 배포 후의 네 집합 검사를 구분한다.

원문이나 맥락이 없거나 실제 검수를 끝내지 못했으면 그 범위는 미완료로 남긴다. API 장애 시에도 직접 경로로 진행할 수 있지만, 어느 경로도 전수 검수를 수행하지 못하면 배포를 중단한다. 크레딧 구매/충전을 사용자에게 불필요하게 요구하지 않는다.

## 명시적으로 승인된 부분 배포

배포할 수 없는 장면이 있다면 제외할 정확한 ID, 남을 원문 범위, 나머지 검수 결과를 먼저 알린다. 사용자가 해당 범위의 부분 배포를 승인한 경우에만 그 범위로 배포 게이트를 평가한다. 포함한 파일의 전수 검수·레이아웃·태그·수치·해시 검사는 모두 통과해야 한다. 전체 캐시 감사에서 제외 파일이 누락으로 보고되는 사실은 기록에 그대로 남기고, 전체 완료나 전체 감사 통과로 표현하지 않는다. 검사를 느슨하게 만들거나 미번역 원문을 한국어 파일로 채워 넣어 누락을 숨기지 않는다.
